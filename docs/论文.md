# 基于机器学习的健身计划推荐系统设计与实现

## 第 1 章 绪论

### 1.1 研究背景与意义

随着社会经济的发展与国民健康意识的觉醒，健身逐步融入大众的日常生活，健身行业对个性化服务的需求快速增长。然而，传统健身行业以及主流健身软件多采用通用健身模板，忽视了用户在身体素质、运动基础、可支配时间、饮食习惯等方面的个体差异。这种“千人一面”的模式容易造成健身目标匹配度低、训练效果差，严重时还可能引发运动损伤。因此，将人工智能技术与健身场景相结合，开发智能化的健身推荐系统，是解决行业痛点的现实需要。

从理论层面看，本研究探究随机森林集成算法在多维用户特征输入条件下完成健身计划多类别推荐的适配能力与特征优化方案。针对开源数据集与本土化问卷构成的多源健康数据，完成编码、融合与平衡处理，为健身领域异构数据的量化处理提供实践案例，拓展个性化推荐系统在运动健康方向的应用场景。

从实践层面看，本系统面向普通健身使用者，完成健身计划智能筛选、训练记录管理与身体指标趋势分析，解决传统健身方案匹配度低、用户坚持困难的痛点。依靠数据驱动给出科学健身建议，降低用户试错成本与运动损伤风险，为健身智能化提供一套轻量、可落地的 Web 技术解决方案。

### 1.2 国内外研究现状

国内针对健身推荐系统已有一定研究，但大多采用 BMI 规则判断、协同过滤等基础方法[2][4]。现有系统所使用的数据集大多仅有几千条样本，特征维度有限，通常仅使用性别、BMI、健身目标等基础字段，缺少心率、运动经验、身体素质等级等细粒度特征，模型难以适配用户身体状态的动态变化，个性化与自适应能力有待提升[5]。

国外运动健康建模研究起步更早。Kaggle 平台公开了多套健身数据集：MealPlan and Exercise Schedule 共 80000 条样本，记录性别、健身目标、BMI 等级以及训练与饮食方案；Gym Members Exercise Dataset 含 973 条真实健身记录；Body Performance Dataset 有 13393 条身体素质测评数据。国外研究依托上述数据集运用机器学习技术实现用户长期健身状态画像追踪，在个性化运动处方与目标设定方面取得了进展[8][9][10]，为本课题的数据选择、特征处理与随机森林模型调优提供了技术参考。

总体来看，现有研究在健身推荐领域已经积累了一定的数据与技术基础，但在多维特征融合、数据不平衡处理以及“采集—建模—推荐—反馈”的完整闭环方面仍有提升空间。本课题正是针对上述不足，构建覆盖完整业务流程的健身计划推荐系统。

### 1.3 主要研究内容

本课题围绕以下核心内容展开：

（1）系统需求分析与设计。梳理面向个人健身指导的业务流程，明确系统所需实现的用户信息采集、计划推荐、数据记录及可视化分析等核心功能模块。

（2）用户特征建模与多源数据处理。结合 Kaggle 开源数据集、网络问卷调查数据及其他开源数据，构建全方位的用户健身画像，完成特征的清洗、量化与编码转换。

（3）推荐算法设计与优化。选用随机森林算法构建核心推荐模型，利用其在多维特征分类上的优势，实现系统根据用户画像自动匹配适宜的训练动作、强度与周期。

（4）系统功能开发。采用前后端分离架构，前端基于 Vue 框架，后端基于 Python 的 FastAPI 框架，开发包含用户管理、推荐计算、训练记录分析及可视化呈现等模块。

（5）系统测试验证。在构建的数据集上对模型进行训练和评估，测试系统的接口响应速度与推荐合理性，验证健身计划的科学性。

## 第 2 章 相关技术概述

### 2.1 FastAPI 框架

FastAPI 是一个基于 Python 的高性能异步 Web 框架，其底层依赖于 Starlette 与 Pydantic。FastAPI 具有以下特点：其一，基于 Python 类型注解自动完成请求参数校验与响应模型序列化，减少样板代码；其二，自动生成交互式的 Swagger UI 接口文档，便于前后端联调；其三，原生支持异步编程，具备较高的并发性能。本系统采用 FastAPI 构建后端 RESTful 接口，并利用其自动文档特性完成接口的快速验证。

### 2.2 Vue 与 ECharts

Vue 是一套用于构建用户界面的渐进式 JavaScript 框架，采用组件化开发模式，配合 Vue Router 与 Pinia 可实现单页应用的路由管理与状态管理。本系统前端采用 Vue 3 与 Vite 构建，并通过 Axios 封装与后端的交互。ECharts 是一个基于 JavaScript 的开源可视化图表库，支持折线图、柱状图等多种图表类型，本系统使用其绘制训练完成率趋势与体重变化趋势。

### 2.3 随机森林算法

随机森林是一种基于决策树的集成学习算法，通过自助采样构建多棵决策树，并对各树的结果进行投票或平均得到最终输出。随机森林对多维特征具有良好的处理能力，能够输出特征重要性，且对过拟合具有一定的抑制作用。本系统将随机森林用于健身计划的多分类推荐，输出训练目标、训练频率、训练强度等结构化标签。

### 2.4 SMOTE 算法

SMOTE（Synthetic Minority Over-sampling Technique）是一种处理类别不平衡的过采样方法。该方法通过在少数类样本与其近邻样本之间进行插值，合成新的少数类样本，从而平衡各类别的样本数量。本系统针对健身目标样本分布不均的问题，采用 SMOTE 对少数类进行过采样，避免模型偏向样本量较大的类别。

## 第 3 章 系统需求分析与设计

### 3.1 功能需求

本系统面向普通个人健身用户，核心功能包括：用户注册与登录、用户画像录入、健身计划智能推荐、训练记录管理、动态调整建议以及数据可视化。系统以 9 项身体与习惯特征作为输入，输出训练目标、每周训练频率、动作组合、单次训练时长、训练强度等级与训练周期共 6 类推荐结果。

9 项输入特征分别为：性别、年龄、身高、体重、运动目标、运动基础、每周可用时间、饮食偏好与运动伤病，其中体重与身高可派生身体质量指数 BMI。运动伤病采用多选形式，各部位之间相互独立，“无”与其他部位互斥。

### 3.2 非功能需求

在性能方面，推荐接口的响应时间在 95 分位应不超过 500 毫秒。在安全方面，密码采用 bcrypt 加盐哈希存储，接口采用 JWT 鉴权，并通过 CORS 白名单控制跨域访问。在数据质量方面，需对多源数据完成去重、异常过滤、缺失值填充与类别平衡处理，保证训练数据质量。

### 3.3 系统架构

系统采用前后端分离的三层架构：前端为 Vue 单页应用，负责用户交互与数据展示；后端为 FastAPI 服务，负责业务逻辑与模型推理；数据层采用 SQLite 进行持久化存储，开发阶段使用 SQLite 以简化部署，后续可通过连接串切换为 MySQL。后端通过加载训练完成的随机森林模型，结合动作库与计划模板完成推荐结果的组装。

### 3.4 数据库设计

系统共设计 7 张数据表：用户表（user）、用户画像表（user_profile）、推荐记录表（recommendation_record）、训练记录表（training_record）、身体指标表（body_metric）、动作字典表（exercise）与计划模板表（plan_template）。其中用户画像表存储 9 项输入特征，运动伤病以 JSON 数组形式存储；动作字典表与计划模板表构成动作组合的静态字典，供推荐接口按训练目标与强度查询动作组合。

## 第 4 章 数据预处理与模型构建

### 4.1 数据来源

本课题使用的数据包括 Kaggle 平台的三套健身数据集与本土化问卷数据。MealPlan and Exercise Schedule 数据集共 80000 条样本，记录性别、健身目标、BMI 等级以及训练与饮食方案，作为标签主数据集；Gym Members Exercise Dataset 含 973 条真实健身记录，提供年龄、身高、体重、BMI、运动经验与训练频率等生理与运动特征；Body Performance Dataset 含 13393 条身体素质测评数据，提供身体脂肪率、血压、握力、仰卧起坐等生理指标。此外，通过网络问卷采集本土化用户样本，与开源数据集共同构成多源数据。

### 4.2 数据清洗

针对多源数据存在的重复、异常与缺失问题，采用 Pandas 进行清洗。首先去除重复记录，其次对数值型特征按中位数填充缺失值，对类别型特征按众数填充，最后采用 winsorize 方法按 1% 与 99% 分位数对数值型特征进行截断，抑制极端异常值的影响。清洗后可用样本规模约为 94866 条。

### 4.3 特征工程与编码

将各数据集的字段映射到统一的 9 项输入特征，并由身高与体重派生 BMI。类别型特征采用标签编码，运动伤病采用多标签独热编码，数值型特征采用标准化处理。为统一编码规则，系统保存了标签编码器、多标签编码器与标准化器，保证训练阶段与推理阶段的编码方式保持一致。

### 4.4 SMOTE 类别平衡

由于训练集中不同健身目标的样本数量分布不均，采用 SMOTE 对少数类进行过采样。过采样前减脂样本约为 32143 条，保持健康样本约为 7871 条；过采样后各类别样本量均平衡为 32143 条，有效缓解了类别不平衡带来的分类偏差。

### 4.5 模型训练与调优

选用随机森林算法构建多分类模型，采用网格搜索对 n_estimators 与 max_depth 两个超参数进行调优，以加权 F1 作为评分指标。实验得到最优超参数组合为 n_estimators=50、max_depth=10。在测试集上，训练目标的加权 F1 达到 1.0000，训练频率、训练时长、训练强度与训练周期的准确率均接近 1.0。特征重要性分析表明，运动目标特征的贡献最高，其次为运动伤病、年龄等特征。
